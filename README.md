# BAIGR — نظام البحث عن العملاء والتواصل معهم

نظام أتمتة كامل على n8n: يبحث عن عملاء محتملين، يحلّل مشكلة كل واحد منهم،
يكتب له رسالة واتساب مخصّصة، يعرضها عليك في تلجرام للموافقة **واحدة واحدة**،
ثم يرد على من يرد كمسؤول مبيعات — ويصمت فوراً إذا تدخّلت أنت.

**الحالة: الـ6 workflows منشورة ومفعّلة. بقيت خطوة واحدة — شغّل
[`db/schema.sql`](db/schema.sql) في Supabase SQL Editor، ثم أرسل `/start` للبوت.**
التفاصيل في [`docs/SETUP.md`](docs/SETUP.md).

---

## المبدأ الأساسي

> البحث جماعي. الإرسال فردي.

النظام يجلب 50 أو 100 عميل في البحث الواحد، لكنه **لا يرسل شيئاً أبداً** بدون
ضغطة زر منك على كل رسالة على حدة. لكل عميل بطاقتان في تلجرام: واحدة تشرح من هو
وما مشكلته، وواحدة فيها الرسالة نفسها مع ثلاثة أزرار: إرسال، تعديل، حذف.

## المكوّنات

| Workflow | ماذا يفعل |
|---|---|
| **BX · Telegram Brain** | المحادثة معك، وأزرار كل بطاقة |
| **BX · Lead Engine** | خرائط جوجل → قراءة موقع كل محل → تحليل AI → كتابة الرسالة |
| **BX · Queue Pusher** | يعرض العميل التالي بعد كل قرار |
| **BX · WhatsApp Send** | الباب الوحيد للخروج إلى واتساب |
| **BX · WhatsApp Inbound AI** | يرد على العملاء، يفهم الصوت، ويتنحّى إذا تدخّلت |
| **BX · Export Report** | ملف Excel بكل شيء |

`db/schema.sql` ينشئ الجداول الثمانية التي يقوم عليها كل ما سبق.

## ثلاثة قرارات تصميم تستحق الشرح

**1. كل رسالة تمر من باب واحد.**
لا شيء في النظام يتصل بواتساب مباشرة — كل شيء يمر عبر `BX · WhatsApp Send`.
لذلك مفتاح الإيقاف (`live_sending`) والحد اليومي (`daily_send_cap`) وسجل
الإرسال لا يمكن الالتفاف عليها من أي مسار.

**2. الـAI لا يخترع مشاكل.**
قبل استدعاء الـAI، يفتح النظام موقع المحل ويستخرج إشارات ملموسة قابلة للتحقق:
هل يوجد زر حجز؟ هل يوجد واتساب؟ هل الموقع متجاوب مع الجوال؟ كم عدد المراجعات؟
الـAI يرى هذه الإشارات فقط، ومطلوب منه أن يشير إلى دليل محدد. إن لم يجد دليلاً،
تنخفض درجة الملاءمة والعميل يُستبعد تلقائياً.

**3. يعمل بلا أي اعتماد خارجي.**
الوضع الافتراضي `whatsapp_driver = wame`: لا VPS، لا اشتراك، ولا احتمال حظر رقم.
تضغط ✅ فيفتح لك تلجرام زر واتساب والرسالة جاهزة وتضغط إرسال بيدك، والنظام يسجّل
ويتابع كالمعتاد. الإرسال الآلي إضافة تفعّلها لاحقاً، لا شرط للبدء.

## ما يجب أن تعرفه قبل التشغيل

**ربط رقم واتساب عادي عبر Evolution API مخالف لشروط استخدام واتساب، وMeta قد
تحظر الرقم.** اخترنا هذا الطريق لأنك طلبت رسائل حرة تبدو مكتوبة بيد بشر، وأن
تستطيع فتح واتساب والتدخل بنفسك — وواتساب الرسمي (Cloud API) لا يسمح بأي من
الاثنين: أول رسالة لعميل جديد يجب أن تكون قالباً معتمداً من Meta، والرقم المربوط
بالـAPI لا يُفتح على تطبيق واتساب.

الخطر حقيقي. قلّله بالبدء بـ20 رسالة يومياً، وبرقم ثانوي، وباحترام `daily_send_cap`.
تفاصيل أوفى في [`docs/SETUP.md`](docs/SETUP.md#4-ربط-الواتس-اب).

وإذا أردت صفر مخاطرة: اضبط `whatsapp_driver = wame`. عندها يعطيك تلجرام زراً
يفتح واتساب والرسالة جاهزة وتضغط إرسال بيدك، وكل ما تبقّى في النظام يعمل كما هو.

## الخدمات التي يعرضها النظام

مُعرّفة في جدول `bx_services`، والـAI **لا يستطيع** اقتراح شيء خارجها:

| الرمز | الخدمة | لمن |
|---|---|---|
| `WEBSITE` | موقع إلكتروني | لا موقع، أو موقع قديم/بطيء/غير متجاوب |
| `ECOMMERCE` | متجر إلكتروني | يبيع عبر إنستغرام/واتساب فقط |
| `BOOKING` | نظام حجز مواعيد | عيادات، حلاقين، مراكز تجميل |
| `WHATSAPP` | بوت واتساب للرد | رسائل كثيرة بلا رد |
| `CREATIVE` | صور وفيديو بالذكاء الاصطناعي | محتوى ضعيف |
| `ADS` | إدارة حملات وإعلانات | لا إعلانات، أو إعلانات بلا قياس |
| `AUTOMATION` | نظام أتمتة | عمل يدوي متكرر |

لتعديل القائمة: عدّل `bx_services` **و** قائمة الخدمات في رسالة النظام داخل
عقدة `AI Lead Analyst` في `BX · Lead Engine`.
