## أول تجربة

أرسل `/start` للبوت. ثلاثة أسئلة فقط — **لا يسألك عن عدد**:

```
🌍 في أي دولة نبحث؟        →  الأردن
📍 وفي أي مدينة أو منطقة؟   →  عمان — الدوار السابع
🏪 ما هو النشاط؟           →  عيادات أسنان
```

ثم يبدأ البحث فوراً: يبحث في خرائط جوجل وفي جوجل نفسه وفي إنستغرام وفيسبوك،
يفتح موقع كل محل، يقرأ حساباته وبايو الإنستغرام، ويستدعي الـAI لكل واحد.

**لا تنتظر انتهاء البحث كله.** يجمع النظام أسماء المحلات وأرقامها، ثم يحلّل
أول واحد ويرسل بطاقته ويتوقف عندها. الباقي يبقى خاماً بلا تحليل.

وحين تضغط زراً، يبدأ تحليل التالي في تلك اللحظة — فتصل الرسالة بسلامٍ مضبوط
على الساعة الحالية وببحثٍ طازج. انتظار نصف دقيقة، يظهر خلاله `⏳ عم حلل
العميل التالي...`

كل عميل يأتي في **بطاقتين**.

**البطاقة الأولى — من هو وما مشكلته:**

```
🎯 عميل محتمل
🏪 عيادة سمايل لطب الأسنان
🗂 Dentist
📍 عمان, الأردن
⭐ 4.2 (38)

📞 الهاتف: +962 7 9000 0000
🌐 الموقع: https://smile.jo
📸 إنستغرام: https://www.instagram.com/smiledental
👥 فيسبوك: https://www.facebook.com/smiledental
🗺 الموقع على خرائط جوجل

📝 البايو
عيادة أسنان · عمان · حجز بالاتصال

🔍 المشكلة التي رصدناها
لا يوجد نظام حجز على الموقع، الحجز بالاتصال فقط خلال الدوام

📌 الدليل
الموقع يعرض رقم هاتف فقط ولا يحتوي على أي زر حجز أو نموذج

💡 الخدمة المقترحة
نظام WhatsApp للشركات

🎯 زاوية الإقناع
المريض الذي يبحث ليلاً لا يستطيع الحجز فيذهب لعيادة أخرى

━━━━━━━━━━━━━━━━━━
📊 التقييم
مدى الملاءمة: 78 من 100
الأولوية: 72 من 100
لغة الرسالة: العربية
```

> كل ما تقرأه أنت — المشكلة والدليل وزاوية الإقناع — بالعربية دائماً، حتى لو
> كان البحث في تركيا أو أوروبا. اللغة الأجنبية الوحيدة المسموحة هي **الرسالة**
> نفسها، لأنها تُقرأ من صاحب المحل لا منك.

**البطاقة الثانية — الرسالة والأزرار:**

```
✍️ الرسالة الجاهزة إلى عيادة سمايل لطب الأسنان
━━━━━━━━━━━━━━━━━━

مساء الخير دكتور، مريت على موقع عيادة سمايل...

━━━━━━━━━━━━━━━━━━
📱 سترسل إلى: +962790000000

     [ ✅ إرسال ]  [ ✏️ تعديل ]  [ 🗑 حذف ]
          [ ➡️ التالي بدون قرار ]
```

- **✅ إرسال** → في الوضع اليدوي تتحدّث البطاقة ويظهر زر يفتح واتساب والرسالة
  مكتوبة جاهزة. ترسلها ثم تضغط **«✅ أرسلتها»** فيسجّلها النظام ويتابع الرد.
  في وضع الإرسال الآلي تخرج الرسالة مباشرة دون أي خطوة إضافية.
  **ثم يظهر العميل التالي وحده.**
- **✏️ تعديل** → يسألك ماذا تريد أن تغيّر. اكتب مثلاً «خليها أقصر» أو «احكي
  باللهجة الأردنية» أو «ركّز على موضوع الحجز». يعيد كتابتها ويحدّث نفس البطاقة
  بنفس الأزرار. عدّل كما تشاء حتى ترضى. (التعديل لا يمضي للتالي — أنت ما زلت
  على هذا العميل.) لا يقصّر الرسالة من تلقاء نفسه — يحافظ على طولها وفقراتها
  إلا إذا طلبت أنت غير ذلك.
- **🗑 حذف** → لا يُرسل شيء، **ويظهر العميل التالي وحده.**
- **➡️ التالي بدون قرار** → يتخطّاه للسرعة دون أن يبتّ فيه. بطاقته تبقى في
  المحادثة وأزرارها تعمل متى رجعت إليها.

**واحد في كل مرة، بلا توقف.** بعد كل إرسال أو حذف أو تخطٍّ يظهر التالي تلقائياً،
ويستمر الأمر حتى ترسل `/start` من جديد — عندها يتوقف ويبدأ بحثاً جديداً.
`/next` يستدعي التالي يدوياً في أي وقت.

**«التالي» يعني التالي في بحثك أنت.** كل محل يُحفظ ومعه مفتاح بحثه — النشاط
والمدينة والبلد كما طلبتها، بعد توحيد الهمزات والتاء المربوطة والتشكيل. و`/next`
يقرأ بحثك الشغّال من `bx_sessions` ويطوي حقوله بالطريقة نفسها، فلا يمكن أن يعرض
عليك محلاً من بحث سابق: كنت على عيادات أسنان في الدمام فجاءك جيم في القاهرة —
هذا لم يعد ممكناً.

> إن خلص بحثك الحالي قال لك ذلك وذكر النشاط والمدينة والبلد، وطلب `/start`
> لبحث جديد — ولا ينتقل إلى بحث آخر من تلقاء نفسه. وإن لم يكن هناك بحث شغّال
> أصلاً رد: «ما في بحث شغّال حالياً».

## `/settings` — بدل لوحة التحكم

يعرض لك الوضع الحالي وتحته أزرار:

| الزر | ماذا يفعل |
|---|---|
| 🟢/🔴 الإرسال الآلي | يشغّل أو يطفئ خروج الرسائل فعلياً |
| 📤 بدّل طريقة الإرسال | يدوي ← Evolution ← Cloud API ← يدوي |
| 🗺 مفتاح الخرائط | مفتاح Places API — يجلب المحلات من خرائط جوجل |
| 🔍 مفتاح البحث | مفتاح Custom Search API — يجوز يكون من مشروع Google ثانٍ. اتركه فارغاً ليستخدم مفتاح الخرائط |
| 🔎 معرّف محرك البحث | Search engine ID — يفعّل البحث في إنستغرام وفيسبوك وجوجل |
| 📊 الحد اليومي | أقصى عدد رسائل في اليوم |
| 🌐 رابط Evolution | عنوان الخادم |
| 📛 اسم Instance | اسم الـinstance |

كل تغيير يُحفظ فوراً وتتحدّث نفس الرسالة أمامك.

> عند التبديل إلى الوضع اليدوي يُطفأ الإرسال الآلي تلقائياً — لا معنى لتشغيله
> على قناة لا ترسل بنفسها.

> **هذه الشاشة للبحث وحده.** موظف الواتساب له شاشته `/agent`: مفتاح مستقل، وقناة
> مستقلة، ولا حد يومي عليه — لأن الرد على من كتب لك ليس رسالة باردة، وتحديده لا
> يحمي الرقم، يترك ناساً بلا جواب فقط.

## `/agent` — شاشة الموظف

| الزر | ماذا يفعل |
|---|---|
| 🟢/🔴 شغّل / أطفئ الموظف | المفتاح الرئيسي. مطفأ افتراضياً |
| 📡 بدّل قناة الرد | Cloud API ← Evolution ← يدوي ← Cloud API |
| ⏰/🔴 شغّل / أطفئ المتابعة | متابعة من سكت |
| 🕘 أوقات الدوام | نصّ حر يقوله الموظف للعميل كما كتبته |
| 🌍 المنطقة الزمنية | بصيغة IANA — تمنع خروج متابعة ليلاً |
| 📆 خطة المتابعة | ساعات مفصولة بفواصل، مثل `48,120` |
| 🆔 معرّف Twilio | الـAccount SID — يبدأ بـ `AC`. يظهر فقط عند اختيار Twilio |
| 📞 رقم Twilio | رقم الإرسال بصيغة دولية |

الشاشة تقول لك أيضاً كم معلومة في `/kb`، وتحذّرك إن كان الموظف مشغّلاً على قناة
يدوية — أي مشغّل ولا يستطيع الرد.

## 🔎 تفعيل البحث في إنستغرام وفيسبوك وجوجل

بدون هذه الخطوة يبحث النظام في **خرائط جوجل وحدها**. ومعها يبحث في أربعة مصادر
معاً في كل عملية:

| المصدر | الاستعلام | لماذا |
|---|---|---|
| Google Places | عدة صياغات للنشاط والمنطقة | المحلات المسجّلة على الخرائط |
| إنستغرام | `site:instagram.com <النشاط> <المنطقة>` | محلات كثيرة لا وجود لها على الخرائط أصلاً |
| فيسبوك | `site:facebook.com <النشاط> <المنطقة>` | الصفحات التجارية القديمة |
| جوجل العام | `<النشاط> <المنطقة> whatsapp` | من ينشر رقم واتساب في صفحته أو دليله |

ثم تُدمج النتائج كلها، ويُسقط منها من هو محفوظ عندك سابقاً، ولا يبقى إلا من
أمكن استخراج رقم قابل للمراسلة له.

**لماذا لا نفتح إنستغرام مباشرة؟** جرّبناها فعلياً: صفحة إنستغرام تفتح (612KB،
بدون حاجز تسجيل دخول) لكنها **لا تحتوي على البايو ولا رابط الموقع** — إنستغرام
صار يحمّل بيانات الحساب من داخل المتصفح بتوكن مصادقة. وفيسبوك يرد `400`،
وDuckDuckGo يرد `202` (حاجز بوتات). لا طريق مباشر يعمل.

**الطريق الذي يعمل:** جوجل فهرس الحساب من قبل، **والبايو محفوظ في نص نتيجة
البحث نفسها**. فنسأل جوجل بدل أن نسأل إنستغرام — ونحصل على الرابط والبايو معاً
في استدعاء واحد.

للتفعيل (خمس دقائق، مرة واحدة):

**مفتاحان لا مفتاح واحد.** Places و Custom Search لا يشترط أن يكونا في نفس
مشروع Google Cloud، ومفتاح الخرائط غالباً مقيّد على Places وحده فيرفض البحث
بـ`403 ... are blocked`. لذلك للبحث مفتاحه المستقل:

1. [Google Cloud Console](https://console.cloud.google.com/apis/library/customsearch.googleapis.com)
   → **ENABLE** لتفعيل **Custom Search API**
2. نفس المشروع → **Credentials** → **+ Create credentials** → **API key**
3. على المفتاح الجديد: **Restrict key** → **Custom Search API** فقط → **SAVE**
4. التلجرام → `/settings` → **🔍 مفتاح البحث** → الصق المفتاح الجديد
5. [programmablesearchengine.google.com](https://programmablesearchengine.google.com/controlpanel/create)
   → الاسم أي شيء → **What to search?** = **Search the entire web** → **CREATE**
6. انسخ **Search engine ID** من لوحة تحكم المحرك
7. التلجرام → `/settings` → **🔎 معرّف محرك البحث** → الصقه

> إن كان مفتاح الخرائط نفسه غير مقيّد ومفعّل عليه Custom Search، تكفي الخطوات
> 5–7 واترك 🔍 مفتاح البحث فارغاً — النظام يستخدم مفتاح الخرائط تلقائياً.

بعدها يظهر في البطاقة:

```
📸 إنستغرام: https://www.instagram.com/somecafe
👥 فيسبوك: https://www.facebook.com/somecafe
🔗 رابط البايو: https://linktr.ee/somecafe
💬 واتساب بالبايو: +962790000000

📝 البايو
Specialty coffee · Amman · Order via WhatsApp
```

والـAI يقرأ البايو أيضاً، فيلاحظ أشياء مثل: «يبيع عبر إنستغرام فقط»، أو «رابط
البايو Linktree وليس موقعاً حقيقياً»، أو «الطلب عبر واتساب بدون نظام».

**الحصة:** 100 بحث يومياً مجاناً، ثم 5$ لكل 1000. كل بحث عن عملاء يستهلك 3
استدعاءات ثابتة (إنستغرام + فيسبوك + جوجل العام)، بالإضافة إلى استدعاء واحد لكل
محل لم نجد حساباته على موقعه.

## موظف الواتساب — التشغيل

الموظف يرد على من يكتب لك. كل إعداداته من `/agent` في التلجرام، وهو **مطفأ حتى
تشغّله**. الشيء الوحيد الذي لا يُضبط من الجوال هو الويبهوك ومفتاح القناة.

### أولاً: أي قناة؟

السؤال ليس «أيهما أأمن» بل:

> **هل تريد أن تبقى تفتح واتساب هذا الرقم على جوالك؟**

| جوابك | القناة |
|---|---|
| نعم، وأريد أن أتدخّل في المحادثات بيدي | **Evolution API** |
| لا، الرقم للأعمال ولا ألمسه | **Meta Cloud API** أو **Twilio** |

الفرق حقيقي ولا رجعة فيه بسهولة: الرقم المربوط بـCloud API أو بـTwilio **يتوقف عن
العمل على تطبيق واتساب**. وميزة «الموظف يسكت إذا فتحت أنت» تفقد معناها هناك، لأنه
لا يوجد تطبيق تفتحه — ولا يصل إلينا إشعار بما كتبته أنت أصلاً. Evolution يمسح QR
كجهاز مرتبط، فالتطبيق يبقى في يدك.

> **Twilio ليس بديلاً ثالثاً عن هذين.** هو موزّع معتمد (BSP) فوق منصة واتساب
> الرسمية نفسها، فقواعده هي قواعد Cloud API حرفياً: الرقم يخرج من التطبيق، والرد
> الحر مسموح ٢٤ ساعة من آخر رسالة للعميل، وما بعدها يحتاج قالباً معتمداً. الفرق
> أن Twilio أسهل في الربط، وفيه **Sandbox** تجرّب عليه كل شيء خلال دقائق بلا
> تحقّق أعمال وبلا أن تمسّ رقمك.

### Evolution API — التطبيق يبقى على جوالك

**١. خادم ونطاق.** أصغر VPS يكفي (1–2 جيجا رام، أوبنتو 22.04 أو 24.04) ≈ 5$
شهرياً. وجّه نطاقاً فرعياً مثل `evo.yourdomain.com` بسجل A إلى عنوان الخادم.

**٢. دوكر:**

```bash
curl -fsSL https://get.docker.com | sh
mkdir -p /opt/evolution && cd /opt/evolution
```

**٣.** أنشئ `docker-compose.yml`. هذه نقطة بداية — **قارنها بملف `.env.example`
في النسخة التي تنزّلها**، فأسماء المتغيرات تتغيّر بين إصدارات Evolution:

```yaml
services:
  evolution:
    image: evoapicloud/evolution-api:latest
    restart: always
    ports: ["8080:8080"]
    environment:
      SERVER_URL: https://evo.yourdomain.com
      AUTHENTICATION_API_KEY: مفتاح_طويل_عشوائي_اخترعه_أنت
      DATABASE_PROVIDER: postgresql
      DATABASE_CONNECTION_URI: postgresql://evo:كلمة_سر_قوية@postgres:5432/evolution?schema=public
      CACHE_REDIS_ENABLED: "true"
      CACHE_REDIS_URI: redis://redis:6379/6
      CACHE_REDIS_PREFIX_KEY: evolution
      CONFIG_SESSION_PHONE_CLIENT: BAIGR
      CONFIG_SESSION_PHONE_NAME: Chrome
    volumes: ["evolution_instances:/evolution/instances"]
    depends_on: [postgres, redis]

  manager:
    image: evoapicloud/evolution-manager:latest
    restart: always
    ports: ["3000:80"]

  postgres:
    image: postgres:15
    restart: always
    environment:
      POSTGRES_USER: evo
      POSTGRES_PASSWORD: كلمة_سر_قوية
      POSTGRES_DB: evolution
    volumes: ["postgres_data:/var/lib/postgresql/data"]

  redis:
    image: redis:latest
    restart: always
    command: redis-server --appendonly yes
    volumes: ["evolution_redis:/data"]

volumes:
  evolution_instances:
  postgres_data:
  evolution_redis:
```

```bash
docker compose up -d
```

**٤. HTTPS.** n8n في السحابة، فلا يستطيع مناداة خادمك إلا على HTTPS بشهادة صحيحة.
سطر واحد بـCaddy يكفي ويجدّد الشهادة وحده:

```bash
docker run -d --name caddy --restart always --network host \
  -v caddy_data:/data \
  caddy caddy reverse-proxy --from evo.yourdomain.com --to 127.0.0.1:8080
```

تأكّد أن `https://evo.yourdomain.com` يفتح قبل أن تكمل.

**٥. أنشئ instance وامسح الرمز.** افتح المدير على `http://عنوان_الخادم:3000`،
ضع رابط الـAPI ومفتاح `AUTHENTICATION_API_KEY`، أنشئ instance باسم `baigr`،
وامسح رمز QR من واتساب رقم BAIGR (الإعدادات ← الأجهزة المرتبطة).

الرقم الآن مرتبط كجهاز إضافي — **التطبيق على جوالك يبقى يعمل كما هو**.

**٦. الويبهوك.** في المدير ← الـinstance ← Webhook:

| الحقل | القيمة |
|---|---|
| URL | `https://baigr115.app.n8n.cloud/webhook/bx2-whatsapp-inbound` |
| Events | `MESSAGES_UPSERT` وحده |
| Webhook Base64 | **مفعّل** — بدونه لا تُفهم الرسائل الصوتية |

**٧. في n8n** أنشئ credential من نوع **Custom Auth** بالاسم `Evolution API key`:

```json
{ "headers": { "apikey": "نفس_AUTHENTICATION_API_KEY" } }
```

واربطه بعقدة **Evolution Send** في `BX2 · WhatsApp Send`. هذه الخطوة الوحيدة التي
تبقى خارج التلجرام — مفاتيح n8n لا تُضبط إلا من n8n.

**٨. من التلجرام:**

```
/settings → 🌐 رابط Evolution → https://evo.yourdomain.com
/settings → 📛 اسم Instance   → baigr
/agent    → 📡 بدّل قناة الرد  → حتى تصل إلى 🤖 Evolution
/agent    → 🟢 شغّل الموظف
```

> **لا تشغّل** `/settings` ← 🟢 الإرسال الآلي إلا إذا أردت أن يرسل النظام رسائل
> البحث الباردة بنفسه أيضاً. الموظف له مفتاحه في `/agent`، ويعمل والبحث يدوي.

**٩. جرّب.** ابعث من رقم آخر إلى رقم BAIGR. المتوقّع: يصلك على التلجرام نسخة من
رسالة العميل ومن رد الموظف خلال ~١٥ ثانية (تسع ثوانٍ انتظار + وقت الكتابة).

#### الخطر، وكيف تصغّره

ربط رقم عادي بهذه الطريقة مخالف لشروط استخدام واتساب، وMeta قد تحظر الرقم. هذا
خطر حقيقي لا نظري، وأنت اخترت هذا الطريق عن معرفة لأنك تريد التطبيق في يدك.
ما يصغّره فعلاً:

- **ابدأ برقم ثانوي** لا برقم فيه سنوات من محادثات عملائك.
- الرد على من كتب لك أولاً هو **أقل** أنماط الاستخدام إثارةً للحظر — الحظر يأتي
  من الإرسال الجماعي البارد. أبقِ البحث يدوياً في البداية.
- لا تنقل الرقم إلى الخادم وترسل منه عشرات الرسائل في اليوم الأول.
- أبقِ الجوال متصلاً بالإنترنت؛ الجهاز المرتبط يحتاج الحساب حيّاً.

### Twilio — الأسرع للتجربة

Twilio يعطيك شيئاً لا يعطيه غيره: **Sandbox** تشغّل عليه الموظف كاملاً خلال دقائق،
برقم Twilio مشترك، بلا تحقّق أعمال وبلا أن تلمس رقم BAIGR. ممتاز لتختبر المعرفة
والردود والمتابعة قبل أن تقرّر أي قناة تعتمد.

**١.** من [twilio.com/console](https://www.twilio.com/console) خذ **Account SID**
(يبدأ بـ `AC`) و**Auth Token**.

**٢.** في n8n أنشئ credential من نوع **Basic Auth** بالاسم `Twilio`:

| الحقل | القيمة |
|---|---|
| User | الـAccount SID |
| Password | الـAuth Token |

واربطه بعقدتين: **Twilio Send** في `BX2 · WhatsApp Send`، و**Download Twilio Voice
Note** في `BX2 · WhatsApp Agent` — الثانية هي التي تجلب الرسائل الصوتية، ومن دونها
تصل الرسالة الصوتية ولا تُفهم.

**٣.** في Twilio Console ← Messaging ← Try it out ← **Send a WhatsApp message**،
اتبع تعليمات الـSandbox: أرسل `join <كلمتان>` من جوالك إلى رقم الـSandbox.

**٤.** في نفس الصفحة ← Sandbox settings، ضع في **When a message comes in**:

```
https://baigr115.app.n8n.cloud/webhook/bx2-whatsapp-inbound
```

والطريقة **POST**.

**٥.** من التلجرام:

```
/agent → 📡 بدّل قناة الرد → حتى تصل إلى ☎️ Twilio
/agent → 🆔 معرّف Twilio  → الـAccount SID
/agent → 📞 رقم Twilio    → رقم الـSandbox بصيغة +14155238886
/agent → 🟢 شغّل الموظف
```

الشاشة تعرض لك حالة Twilio، وتقول صراحةً إن كان ناقصاً إعداد.

> **لا ترسل الـAuth Token إلى البوت.** لا يوجد زر يقبله، والبوت يرفضه إن لصقته —
> كل ما يُكتب للبوت ينتهي في جدول، والتوكن مكانه credential داخل n8n وحده.

**٦.** للانتقال من الـSandbox إلى رقم حقيقي: Twilio ← Senders ← WhatsApp senders،
سجّل رقمك (يحتاج تحقّق أعمال من Meta)، ثم بدّل 📞 رقم Twilio إلى الرقم الجديد.
لا شيء آخر يتغيّر.

#### ما لا يعمل على Twilio

| | |
|---|---|
| التدخل بالكتابة من جوالك | الرقم ليس على التطبيق أصلاً |
| «الموظف يسكت إذا فتحت أنت» | لا تصل إشعارات برسائلك أنت، فلا شيء يوقفه — أوقفه من `/agent` |
| مراسلة عميل بعد ٢٤ ساعة من آخر رسالة له | يحتاج قالباً معتمداً من Meta. المتابعة الآلية تصطدم بهذا |

المتابعة الأولى غالباً تقع داخل الـ٢٤ ساعة فتمرّ، والتي بعدها غالباً لا. إن كانت
المتابعة مهمة لك، Evolution هو الذي يعطيها بلا قيود.

### Meta Cloud API — البديل بلا خادم وبلا خطر حظر

إن غيّرت رأيك لاحقاً وقرّرت ألا تفتح الرقم على جوالك: القيد الشهير في Cloud API —
أن أول رسالة لعميل جديد يجب أن تكون قالباً معتمداً من Meta — لا يمسّ الموظف
أصلاً، لأن العميل هو من كتب أولاً، وداخل ٢٤ ساعة من رسالته الرد الحر مسموح تماماً.

**١.** من [developers.facebook.com](https://developers.facebook.com) أنشئ تطبيقاً
وأضف منتج **WhatsApp**. انسخ **Phone number ID** و**Permanent access token**.

**٢.** في n8n أنشئ credential من نوع **Custom Auth** بالاسم `WhatsApp Cloud API`:

```json
{ "headers": { "Authorization": "Bearer التوكن_الدائم" } }
```

واربطه بعقدة **Cloud API Send** في `BX2 · WhatsApp Send`.

**٣.** في جدول `bx_config` داخل n8n ضع الـPhone number ID في `cloud_phone_number_id`،
وأي نصّ تختاره في `meta_verify_token`.

**٤.** في إعدادات التطبيق ← WhatsApp ← Configuration، وجّه الـwebhook إلى نفس
العنوان أعلاه، والـVerify token هو ما كتبته في `meta_verify_token`. اشترك في حقل
**messages**.

**٥.** `/agent` ← 📡 بدّل قناة الرد حتى تصل إلى 🏢 Meta Cloud API، ثم 🟢 شغّل الموظف.

### ثم املأ المعرفة

الموظف لا يقول إلا ما في `/kb`. خدمات BAIGR معبّأة مسبقاً، لكن **بلا أسعار ولا
مدد تسليم**. أضفها:

```
/kb كم سعر الموقع = بيبدا من ٣٠٠ دينار وبيوصل حسب عدد الصفحات
/kb قديش بياخد الموقع = من أسبوعين لشهر حسب الحجم
/kb بتقبلوا دفع بالتقسيط = نص المبلغ بالبداية والنص عند التسليم
```

`/kb` وحدها تعرض الكل، و`/kb حذف 3` تشيل واحدة. كل ما لم تكتبه سيحوّله الموظف
إليك بدل أن يخترع جواباً.

### وأخيراً المتابعة

`/agent` → ⏰ شغّل المتابعة، و🕘 أوقات الدوام، و🌍 المنطقة الزمنية (مثال:
`Asia/Amman`). المنطقة الزمنية هي التي تمنع خروج متابعة الثالثة فجراً.

خطة المتابعة الافتراضية `48,120`: المتابعة الأولى يحدّد وقتها الموظف من كلام
العميل نفسه، ثم واحدة بعد ٤٨ ساعة، ثم واحدة بعد ١٢٠ — ثلاث متابعات ثم يتوقف.

**التدخل اليدوي:** افتح واتساب على جوالك واكتب في المحادثة. النظام يميّز رسالتك
عن رسائله هو، فيُطفئ الرد الآلي في هذه المحادثة وحدها فوراً ويخبرك. من تلك اللحظة
أنت المسؤول عنها.

النظام يصمت ويطلب تدخلك تلقائياً إذا: كان العميل غاضباً، أو اشتكى، أو طلب
مسؤولاً، أو طلب عدم مراسلته، أو سأل شيئاً ليس في `/kb`. وإن بقيت المحادثة تنتظرك
٢٤ ساعة، يذكّرك بها.

## لاحقاً: الإرسال الآلي للبحث

هذه ميزة منفصلة عن الموظف: أن يرسل النظام رسائل البحث الباردة بنفسه بدل أن تضغط
أنت. تحتاج جسر واتساب — الشيء الوحيد الذي يتطلب اشتراكاً — ولا يصلح لها Cloud API
لأن أول رسالة لعميل جديد يجب أن تكون قالباً معتمداً.

**1.** نصّب Evolution API (أو WAHA) على VPS — حوالي 5$ شهرياً. أنشئ instance
وامسح رمز QR برقم واتساب الذي ستستخدمه.

**2.** من التلجرام: `/settings` →
- 🌐 رابط Evolution → `https://evo.yourdomain.com`
- 📛 اسم Instance → اسم الـinstance
- 📤 بدّل طريقة الإرسال → حتى تصل إلى Evolution
- 🟢 شغّل الإرسال الآلي

**3.** في n8n أنشئ credential باسم `Evolution API key` من نوع **Custom Auth**:

```json
{ "headers": { "apikey": "مفتاح_Evolution" } }
```

واربطه بعقدة **Evolution Send** في `BX2 · WhatsApp Send`.
(هذه الخطوة الوحيدة التي تبقى خارج التلجرام — مفاتيح n8n لا تُضبط إلا من n8n.)

> الحد اليومي والإرسال الآلي في `/settings` يخصّان **البحث وحده**. الموظف له
> مفتاحه وقناته في `/agent`، ولا حد يومي عليه: الرد على من كتب لك ليس رسالة باردة.

## عندما لا يعمل شيء

| العرض | السبب |
|---|---|
| البوت لا يرد | تأكد أن `BX2 · Telegram Brain` مفعّل في n8n |
| «انتهى البحث» مع 0 عملاء | مفتاح Google منتهي، أو النشاط/المدينة بلا نتائج |
| «لم أجد عملاء جدد» | كلهم موجودون من بحث سابق — جرّب مدينة أو نشاطاً آخر |
| النتائج من الخرائط فقط | ينقص مفتاح البحث أو معرّف المحرك — بدونهما لا يعمل إلا Places |
| لا يظهر عميل بعد الإرسال | انتهى الطابور — `/start` لبحث جديد |
| البحث بدأ ولم يصل عميل | انتظر دقيقة، أو أرسل `/next` — التحليل يستغرق ~15 ثانية لكل عميل |
| البحث توقف بعد عميل واحد | عقدة `Offer This Lead Now` فقدت `alwaysOutputData` — بدونها تتوقف الحلقة |
| البحث انتهى بلا كروت رغم إيجاد عملاء | كرت قديم لم تُتّخذ فيه قرار كان يقفل الطابور. بوابة «واحد على الشاشة» صارت تحسب كروت هذه الجولة فقط |
| «⚠️ الرسالة انكتبت بس الكرت ما انبعت» | العميل محفوظ جاهز — `/next` يعرضه. إن تكرر، افحص مدخلات `Offer This Lead Now`: أي `only_if_idle` أو `min_ready` متبقٍّ من التصميم القديم يحجز كل بطاقة |
| «⚠️ التحليل ما اشتغل» | خطأ من مزوّد الـAI، غالباً رصيد Anthropic. افتح Plans & Billing، ثم `/next`. المحلات المحفوظة تعود للطابور تلقائياً |
| ضغطت زراً ولم يصل شيء | التحليل يبدأ عند الضغط ويستغرق ~نصف دقيقة. إن طال، راجع تنفيذ `BX2 · Lead Engine` بوضع `mode: next` |
| «خلصوا العملاء» بسرعة | البحث وجد قليلاً. `/start` بمدينة أو نشاط أوسع |
| `MESSAGE_NAMES_THE_AGENCY` في سبب التخطي | النموذج ذكر اسم الشركة في الرسالة. الحارس يرفضها ويجرّب العميل التالي — لا حاجة لتدخل |
| `MESSAGE_OFFERS_SOMETHING_FREE` | النموذج عرض شيئاً مجانياً. مرفوض تلقائياً لنفس السبب |
| كل العملاء يخرجون بحالة `SKIPPED` | النموذج أعاد `fit_score` بمقياس 0-1. الكود يعيد ضبطها الآن، لكن راجع `Normalize Analysis` إن تكرر |
| `Bad request` من عقدة Claude | `thinkingMode` ليس `adaptive` — Fable 5 يرفض `thinking: disabled` التي ترسلها n8n افتراضياً |
| `/next` يعرض محلاً من بلد أو نشاط آخر | كان يفلتر على الحالة والمحادثة فقط ويرتّب من الأقدم. صار يفلتر على `search_key` المأخوذ من `bx_sessions` — إن تكرر، افحص أن `Build Next Filter` يسبق `Get Next Discovered` |
| «خلصوا العملاء بهالبحث» مع وجود محلات في الجدول | تلك المحلات من بحث أقدم ولا تحمل `search_key` هذا البحث. هذا هو السلوك الصحيح — `/start` لبحث جديد |
| عملاء عالقون بحالة `DISCOVERED` | بقايا تنفيذ توقّف، أو بقايا بحث تركته. لا تظهر في `/next` إلا لبحثها هي. احذفهم إن أردت إعادة اكتشافهم |
| كل الرسائل «الوضع اليدوي» | هذا صحيح ومقصود — غيّره من `/settings` |
| العملاء يردّون بلا رد آلي | الموظف مطفأ (`/agent`)، أو الويبهوك غير مضبوط، أو تدخّلت في المحادثة |
| الرسائل الصوتية لا تُفهم | Webhook Base64 غير مفعّل في Evolution |
| الرسائل الصوتية لا تُفهم على Twilio | credential الـBasic Auth غير مربوط بعقدة `Download Twilio Voice Note` |
| Twilio يسجّل أخطاء 11200 أو 12300 | كان الويبهوك يرد بنصّ عادي. صار يرد TwiML فارغاً — إن تكرر، افحص عقدة `Ack 200 Immediately` |
| `TWILIO_NOT_CONFIGURED` في سجل الإرسال | ينقص الـAccount SID أو رقم الإرسال. `/agent` ← 🆔 و📞 |
| Twilio يرد 63016 أو خطأ قالب | مرّت ٢٤ ساعة على آخر رسالة من العميل. هذا قيد Meta لا قيد النظام |
| متابعة لم تصل على Twilio | غالباً نفس السبب: خارج نافذة الـ٢٤ ساعة |
| «موظف الواتساب مطفأ» على تلجرام | هذا صحيح ومقصود — الموظف لا يشتغل حتى تفتحه من `/agent` |
| الموظف يحوّل كل سؤال إليك | `/kb` فارغة أو ينقصها هذا السؤال. هو لا يخترع جواباً، وهذا هو المطلوب منه |
| الموظف مشغّل ولا يرد أبداً | قناة الرد يدوية. `/agent` ← 📡 بدّل قناة الرد. الشاشة تحذّرك من هذه الحالة نصّاً |
| الرد يصل بعد عشر ثوانٍ | مقصود: ينتظر تسع ثوانٍ ليجمع الرسائل المتتابعة في رد واحد |
| ثلاث رسائل من العميل وردّ واحد | مقصود أيضاً — هذا هو الفرق بين موظف وبوت |
| الرد الآلي انطفأ وحده بعد أول رد | كان يقرأ صدى رسالته هو من Evolution كأنك أنت من كتب. صار يطابقها بسجل الإرسال أولاً — إن تكرر، افحص عقدة `Ours Or Theirs?` |
| لا تخرج متابعات أبداً | `/agent` ← ⏰ شغّل المتابعة. أو الوقت خارج ٩ص–٩م بتوقيت `business_timezone` |
| متابعة وصلت في وقت غريب | المنطقة الزمنية غير مضبوطة فرجع للافتراضي `Asia/Riyadh`. `/agent` ← 🌍 |
| عميل توقفت متابعته قبل الخطة | ردّ، أو قال لا، أو رأى الموظف أن رسالة أخرى ستكون خطأ فأوقفها |
| لا تظهر حسابات سوشال | لم تضبط مفتاح البحث أو معرّف المحرك، أو المحل فعلاً بلا حسابات |
| `403 ... are blocked` | مفتاح البحث مقيّد ولا يشمل Custom Search API |
| المحرك يرجع صفر نتائج | أنشأت المحرك بـ«Search specific sites» بدل **Search the entire web** |

للتشخيص: n8n → **Executions** → افتح آخر تنفيذ فاشل، العقدة الحمراء تخبرك بالسبب.
