# تشغيل نظام BAIGR — خطوة بخطوة

النظام مبني بالكامل على حسابك في n8n. هذا الملف يشرح ما تبقّى لتشغيله.

الترتيب مهم. لا تفعّل أي workflow قبل إنهاء الخطوات 1 إلى 5.

## 1. قاعدة البيانات

افتح Supabase → **SQL Editor** → الصق محتوى `db/schema.sql` بالكامل → **Run**.

الملف آمن للتشغيل أكثر من مرة. ينشئ 8 جداول تبدأ بـ `bx_` — لن يلمس جداولك القديمة.

تحقق أن الجداول ظهرت: `bx_config`, `bx_sessions`, `bx_runs`, `bx_leads`,
`bx_threads`, `bx_messages`, `bx_services`, `bx_send_log`.

---

## 2. الإعدادات في `bx_config`

في Supabase → **Table Editor** → `bx_config` → عدّل الصف الوحيد (id = 1):

| الحقل | ضع فيه | ملاحظة |
|---|---|---|
| `live_sending` | **`false`** | اتركه false حتى تجرّب النظام كاملاً |
| `whatsapp_driver` | `evolution` | أو `wame` للتجربة اليدوية أولاً |
| `owner_chat_id` | رقم محادثتك في تلجرام | مثال: `8638221349` |
| `agency_profile` | فقرة عن BAIGR | تُحقن في كل رسالة يكتبها الـAI |
| `daily_send_cap` | `80` | لا ترفعه فوق 80 في الأسبوع الأول |
| `min_send_gap_seconds` | `45` | |

> **`live_sending = false` هو مفتاح الأمان.** ما دام false، لن تصل أي رسالة إلى
> أي عميل حقيقي مهما ضغطت. البطاقة في تلجرام ستقول لك «الإرسال الفعلي مطفأ»
> وتعطيك زر واتساب لترسل يدوياً. هذا هو الوضع الصحيح للتجربة.

## 3. المفاتيح (Credentials) في n8n

ثلاثة مفاتيح ناقصة. كلها من نوع **Custom Auth** (`httpTemplatedCustomAuth`).
في n8n: **Credentials → Add credential → Custom Auth**.

### أ. Google Places API key — **مطلوب**

الاسم: `Google Places API key`

```json
{ "headers": { "X-Goog-Api-Key": "ضع_المفتاح_هنا" } }
```

المفتاح من [Google Cloud Console](https://console.cloud.google.com/):
أنشئ مشروعاً → فعّل **Places API (New)** → أنشئ API key.

> ⚠️ **مفتاحك القديم مكشوف.** المفتاح `AIzaSyAeonJdd0Fc3o82cwE35MAkyk6PkRg_8Zo`
> مكتوب نصاً داخل الـworkflow القديم `BAIGR Lead Discovery Engine`. أي شخص يرى
> ذلك الـworkflow يستطيع استخدامه على حسابك. **احذفه من Google Cloud وأنشئ
> واحداً جديداً**، وضع الجديد في الـcredential أعلاه فقط.

**التكلفة:** كل بحث عن 50 عميل ≈ 4 استعلامات Text Search. سعر Google حالياً
حوالي 32$ لكل 1000 استعلام، أي ≈ **0.13$ لكل بحث**. Google تعطي رصيداً
مجانياً شهرياً يغطي الاستخدام الخفيف.

### ب. Evolution API key — مطلوب إذا اخترت `evolution`

الاسم: `Evolution API key`

```json
{ "headers": { "apikey": "مفتاح_Evolution" } }
```

### ج. WhatsApp Cloud API token — اختياري

الاسم: `WhatsApp Cloud API token`

```json
{ "headers": { "Authorization": "Bearer التوكن" } }
```

بعد إنشاء كل credential، افتح الـworkflow المعني واربطه بالعقدة:

- `Google Places API key` → عقدة **Google Places Search** في `BX · Lead Engine`
- `Evolution API key` → عقدة **Evolution Send** في `BX · WhatsApp Send`
- `WhatsApp Cloud API token` → عقدة **Cloud API Send** في `BX · WhatsApp Send`

## 4. ربط الواتس اب

اخترت أن تكون الرسالة «عادية كأنها مبعوتة من بشري». هذا يحسم اختيار الطريقة،
ويجب أن تعرف السبب بوضوح:

**واتساب الرسمي (Meta Cloud API) لا يسمح بذلك.** قاعدة Meta: أول رسالة تُرسلها
لشخص لم يراسلك خلال 24 ساعة **يجب** أن تكون قالباً (Template) معتمداً مسبقاً من
Meta. رسالة حرة مخصّصة سترفضها Meta. وأيضاً الرقم المربوط بـCloud API **لا
يمكنك فتحه على تطبيق واتساب العادي** — وأنت طلبت أن تستطيع الدخول والتدخل بنفسك.

لذلك الافتراضي هو **Evolution API** (أو WAHA — نفس الفكرة): جسر يربط رقم
واتساب العادي تبعك، يسمح بأي نص، ويبقى الرقم مفتوحاً على جوالك تدخل وتتدخل
متى شئت.

**المقابل الذي يجب أن تعرفه:** هذا الجسر غير رسمي ومخالف لشروط استخدام واتساب.
Meta **قد تحظر الرقم** إذا رصدت إرسالاً جماعياً أو تلقّت بلاغات من المستقبلين.
هذا خطر حقيقي، ليس نظرياً. لتقليله:

- ابدأ بـ **20 رسالة يومياً** وارفع تدريجياً على مدى أسابيع، لا دفعة واحدة.
- استخدم رقماً ثانوياً في البداية، ليس رقم الشركة الأساسي.
- النظام لا يضع روابط في أول رسالة (الروابط أقوى إشارة سبام) — لا تضفها يدوياً.
- إذا رد أحدهم «لا تراسلني» فالنظام يتوقف تلقائياً. لا تتجاوز ذلك أبداً.
- `daily_send_cap` في `bx_config` هو حدك الصلب. احترمه.

### إعداد Evolution API

1. نصّب Evolution API على VPS (Hetzner/DigitalOcean ≈ 5$ شهرياً)، أو استخدم
   خدمة مستضافة جاهزة.
2. أنشئ instance وامسح رمز QR برقم واتساب الذي ستستخدمه.
3. في `bx_config` املأ:
   - `evolution_base_url` = مثال `https://evo.yourdomain.com`
   - `evolution_instance` = اسم الـinstance
4. في إعدادات الـinstance فعّل الـwebhook على العنوان:

   ```
   https://baigr115.app.n8n.cloud/webhook/bx-whatsapp-inbound
   ```

   فعّل الأحداث: `MESSAGES_UPSERT`
   وفعّل خيار **Webhook Base64** حتى تصل الرسائل الصوتية قابلة للتحويل إلى نص.

### إذا اخترت `wame` بدل ذلك

لا تحتاج VPS ولا اشتراك ولا أي خطر حظر. عند الضغط على ✅ يعطيك تلجرام زراً
يفتح واتساب والرسالة مكتوبة جاهزة، وتضغط إرسال بنفسك. كل شيء آخر في النظام
يعمل كما هو — التتبع، التقرير، والرد الآلي على من يرد.

هذه أفضل طريقة لتجربة أول أسبوع.

## 7. جرّب

أرسل `/start` للبوت. سيسألك بالترتيب:

```
🌍 في أي دولة نبحث؟        →  الأردن
📍 وفي أي مدينة أو منطقة؟   →  عمان — الدوار السابع
🏪 ما هو النشاط؟           →  عيادات أسنان
🔢 كم عميل نبحث عنه؟       →  10        ← ابدأ بعشرة للتجربة
```

ثم انتظر. البحث عن 10 عملاء يستغرق دقيقتين إلى أربع (كل عميل: فتح موقعه +
استدعاء AI). عند الانتهاء تصلك رسالة «انتهى البحث» ثم أول ثلاثة عملاء.

لكل عميل تصلك **بطاقتان**:

**الأولى — من هو وما مشكلته:**
```
🎯 عميل محتمل 1/3
🏪 عيادة سمايل لطب الأسنان
🗂 Dentist
📍 عمان, الأردن
⭐ 4.2 (38)

📞 الهاتف: +962 7 9000 0000
🌐 الموقع: https://smile.jo
📸 سوشال: instagram.com/smile
🗺 الموقع على خرائط جوجل

🔍 المشكلة التي رصدناها
لا يوجد نظام حجز على الموقع، الحجز بالاتصال فقط خلال الدوام

📌 الدليل
الموقع يعرض رقم هاتف فقط، ولا يحتوي على أي زر حجز أو نموذج

💡 الخدمة المقترحة
نظام حجز مواعيد

🎯 زاوية الإقناع
المريض الذي يبحث ليلاً لا يستطيع الحجز فيذهب لعيادة أخرى

📊 ملاءمة 78/100 · أولوية 72 · لغة الرسالة: ar
```

**الثانية — الرسالة نفسها + الأزرار:**
```
✍️ الرسالة الجاهزة إلى عيادة سمايل لطب الأسنان
━━━━━━━━━━━━━━━━━━

مساء الخير دكتور، مريت على موقع عيادة سمايل...

━━━━━━━━━━━━━━━━━━
📱 سترسل إلى: +962790000000

     [ ✅ إرسال ]  [ ✏️ تعديل ]  [ 🗑 حذف ]
```

- **✅ إرسال** → تذهب للواتس، تتحدّث البطاقة، ويظهر العميل التالي تلقائياً.
- **✏️ تعديل** → يسألك ماذا تريد أن تغيّر. اكتب مثلاً «خليها أقصر» أو «احكي
  باللهجة الأردنية» أو «ركّز على موضوع الحجز». يعيد كتابتها ويحدّث نفس البطاقة
  بنفس الأزرار. عدّل كما تشاء حتى ترضى.
- **🗑 حذف** → لا يُرسل شيء، والعميل التالي يظهر.

**عميل واحد في كل مرة.** البحث يجلب 50 أو 100، لكن العرض والإرسال يبقى واحداً
واحداً. `/next` يعرض التالي يدوياً في أي وقت.

### أوامر أخرى

| الأمر | ماذا يفعل |
|---|---|
| `/start` | بحث جديد |
| `/next` | اعرض العميل التالي |
| `/export` | ملف Excel بكل العملاء وحالاتهم |
| `/status` | أين وصلنا |
| `/cancel` | إلغاء |

## 8. الرد الآلي على العملاء

عندما يرد عميل على الواتس:

1. إذا كانت رسالة صوتية → تُحوّل إلى نص أولاً.
2. يُقرأ سجل المحادثة كاملاً مع هذا العميل.
3. يرد **مسؤول مبيعات AI** بلغة العميل ولهجته، برسالة قصيرة تسأل وتفهم قبل أن
   تعرض، ولا تذكر سعراً لأنك لم تعطه قائمة أسعار.
4. تصلك نسخة على تلجرام من رد العميل ومن ردّنا.

**التدخل اليدوي:** افتح واتساب على جوالك واكتب في المحادثة. النظام يرى أن
الرسالة `fromMe` ويُطفئ الرد الآلي في هذه المحادثة فوراً، ويرسل لك تأكيداً على
تلجرام. من تلك اللحظة أنت المسؤول عن هذه المحادثة وحدك.

لإعادة تشغيل الرد الآلي في محادثة: `bx_threads` → غيّر `ai_enabled` إلى `true`.

النظام يصمت ويطلب تدخلك تلقائياً إذا: كان العميل غاضباً، أو طلب مسؤولاً، أو
طلب عدم مراسلته، أو سأل شيئاً لا يعرفه.

## 9. التقرير

`/export` يبني ملف `.xlsx` ويرسله على تلجرام. الأعمدة بالعربية، والصفوف مرتبة:
من ردّ أولاً، ثم من أُرسل له ولم يرد، ثم البقية.

يشمل: الاسم، النشاط، المدينة، الهاتف، الواتس، الموقع، الإيميل، إنستغرام،
خرائط جوجل، التقييم، الخدمة المقترحة، المشكلة، الحالة، تصنيف الرد، نص رد
العميل، تاريخ الإرسال، تاريخ الرد، ونص الرسالة المرسلة.

## عندما لا يعمل شيء

| العرض | السبب الأرجح |
|---|---|
| البوت لا يرد على `/start` | `My workflow` القديم ما زال مفعّلاً |
| «انتهى البحث» مع 0 عملاء | credential الـGoogle Places ناقص، أو النشاط/المدينة بلا نتائج |
| البطاقات لا تظهر | `owner_chat_id` فارغ في `bx_config` |
| كل الرسائل «الإرسال الفعلي مطفأ» | `live_sending = false` — وهذا صحيح حتى تجرّب |
| العملاء يردّون ولا رد آلي | webhook الـEvolution غير مضبوط، أو `ai_enabled = false` لهذه المحادثة |
| الرسائل الصوتية لا تُفهم | خيار Webhook Base64 غير مفعّل في Evolution |

للتشخيص: n8n → **Executions** → افتح آخر تنفيذ فاشل، العقدة الحمراء تخبرك بالسبب.
