# تشغيل نظام BAIGR

كل شيء جاهز ومفعّل. **بقيت خطوة واحدة فقط** — لا أستطيع تنفيذها بنفسي لأن
إنشاء الجداول يحتاج صلاحية SQL على Supabase لا يملكها n8n.

---

## الخطوة الوحيدة: أنشئ الجداول

1. افتح [Supabase](https://supabase.com/dashboard) → مشروعك → **SQL Editor**
2. افتح ملف `db/schema.sql` من هذا المستودع، وانسخ **كل** محتواه
3. الصقه في المحرّر واضغط **Run**

انتظر بضع ثوانٍ. إن ظهر `Success` فقد انتهيت.

الملف آمن للتشغيل أكثر من مرة، ولن يلمس أي جدول من جداولك القديمة (كل جداوله
تبدأ بـ `bx_`).

---

## بعدها مباشرة

افتح بوت التلجرام وأرسل:

```
/start
```

سيسألك بالترتيب:

```
🌍 في أي دولة نبحث؟        →  الأردن
📍 وفي أي مدينة أو منطقة؟   →  عمان — الدوار السابع
🏪 ما هو النشاط؟           →  عيادات أسنان
🔢 كم عميل نبحث عنه؟       →  10        ← ابدأ بعشرة للتجربة
```

البحث عن 10 عملاء يستغرق دقيقتين إلى أربع. عند الانتهاء يصلك أول ثلاثة عملاء،
كل واحد في **بطاقتين**: الأولى من هو وما مشكلته والخدمة المقترحة، والثانية
الرسالة نفسها وتحتها **[✅ إرسال] [✏️ تعديل] [🗑 حذف]**.

بعد كل قرار يظهر العميل التالي تلقائياً.

## لاحقاً: الإرسال الآلي والرد على العملاء

هاتان الميزتان تحتاجان جسر واتساب، وهو الشيء الوحيد الذي يتطلب اشتراكاً:

**1. Evolution API** (أو WAHA) على VPS — حوالي 5$ شهرياً.

بعد تنصيبه ومسح رمز QR برقمك، في Supabase → `bx_config`:

```
whatsapp_driver    = evolution
evolution_base_url = https://evo.yourdomain.com
evolution_instance = اسم الـinstance
live_sending       = true
```

وأنشئ credential في n8n باسم `Evolution API key` من نوع **Custom Auth**:

```json
{ "headers": { "apikey": "مفتاح_Evolution" } }
```

واربطه بعقدة **Evolution Send** في `BX · WhatsApp Send`.

**2. الـwebhook** — في إعدادات الـinstance:

```
https://baigr115.app.n8n.cloud/webhook/bx-whatsapp-inbound
```

الأحداث: `MESSAGES_UPSERT` — وفعّل **Webhook Base64** حتى تُفهم الرسائل الصوتية.

عندها يعمل الرد الآلي: العميل يرد (نصاً أو صوتاً) → يُحوّل الصوت إلى نص → يقرأ
مسؤول المبيعات AI سجل المحادثة ويرد بلغة العميل → تصلك نسخة على تلجرام.

**وإذا فتحت واتساب وكتبت بنفسك، يتوقف الرد الآلي في تلك المحادثة فوراً** ويخبرك.
لإعادته: `bx_threads` → `ai_enabled = true`.

## ⚠️ خطر يجب أن تعرفه قبل تفعيل Evolution

ربط رقم واتساب عادي عبر Evolution API **مخالف لشروط استخدام واتساب، وMeta قد
تحظر الرقم** إذا رصدت إرسالاً جماعياً أو تلقّت بلاغات. هذا خطر حقيقي لا نظري.

اخترنا هذا الطريق لأنك طلبت رسائل حرة تبدو مكتوبة بيد بشر وأن تستطيع التدخل
بنفسك — وواتساب الرسمي (Cloud API) لا يسمح بأيٍّ منهما: أول رسالة لعميل جديد
يجب أن تكون قالباً معتمداً من Meta، والرقم المربوط بالـAPI لا يُفتح على تطبيق
واتساب.

لتقليل الخطر:
- ابدأ بـ **20 رسالة يومياً** وارفع تدريجياً على مدى أسابيع
- استخدم رقماً ثانوياً، لا رقم الشركة الأساسي
- لا تضف روابط في أول رسالة (النظام لا يفعل — لا تفعلها يدوياً)
- `daily_send_cap` في `bx_config` حدك الصلب — احترمه
- من يقول «لا تراسلني» يتوقف النظام عنه تلقائياً؛ لا تتجاوز ذلك

**إن لم ترد المخاطرة إطلاقاً: أبقِ `whatsapp_driver = wame`.** كل شيء يعمل، فقط
الضغطة الأخيرة بيدك.

## 🔐 مفتاح Google — بدّله قريباً

المفتاح المستخدم حالياً هو نفسه القديم، وكان مكتوباً نصاً داخل workflow قديم،
أي أنه **مكشوف**. النظام يعمل به الآن، لكن:

1. Google Cloud → احذف المفتاح القديم وأنشئ واحداً جديداً
2. Supabase → `bx_config` → `google_api_key` → الصق الجديد

خانة واحدة، ولا شيء آخر يتغيّر.

## عندما لا يعمل شيء

| العرض | السبب |
|---|---|
| البوت لا يرد على `/start` | لم تُنشئ الجداول بعد — شغّل `db/schema.sql` |
| «انتهى البحث» مع 0 عملاء | مفتاح Google منتهي أو النشاط/المدينة بلا نتائج |
| البطاقات لا تظهر | `owner_chat_id` فارغ في `bx_config` |
| كل الرسائل «الوضع اليدوي» | `whatsapp_driver = wame` — وهذا صحيح ومقصود |
| العملاء يردّون بلا رد آلي | webhook الـEvolution غير مضبوط، أو `ai_enabled = false` |
| الرسائل الصوتية لا تُفهم | Webhook Base64 غير مفعّل في Evolution |

للتشخيص: n8n → **Executions** → افتح آخر تنفيذ فاشل، العقدة الحمراء تخبرك بالسبب.
